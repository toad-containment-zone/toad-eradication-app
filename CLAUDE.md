# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A no-build, offline-first field app for the TCZ program's **hand-collection (eradication)
sessions**. Each team member runs their own session at a site. The app records a GPS track
every 30 s and the elapsed time, and the collector taps once per toad collected (or "seen, not
caught"). Sites are revisited over several nights so the warehouse can fit a removal model to
the nightly catch vs. effort.

It is the fourth app in the family. **Read `../goanna-hunting-app/CLAUDE.md` first**, then
`../track-monitoring-app/CLAUDE.md` and `../toad-monitoring-app/CLAUDE.md`'s Entities section.
This app was built by copying the track app (session state machine, end-confirm sheet,
active-session persistence, 30 s track with `isFreshFix()`, `prepareTrack()`, toast with Undo,
settings/app-user QR decode, sync) and porting the toad app's known-sites code (manifest CSV
fetch, `parseCsv()`, `allKnownSites()`, Leaflet + Esri imagery). This file documents what's
different.

- `toad-eradication-app.html`: the whole application.
- `toad_eradication_site.xlsx` + `.xml`: site registration form (`form_id`
  `toad_eradication_site`). It creates entities in the `toad_eradication_sites` dataset.
- `toad_eradication_session.xlsx` + `.xml`: session form (`form_id`
  `toad_eradication_session`). It has no entities sheet.
- `manifest.json` / `sw.js` / `index.html`: the PWA shell. `CACHE_NAME` is
  `tcz-eradication-shell-v1`; bump it when the cached files change.

There's no build step or test suite. Serve the directory (`python3 -m http.server`) and open
`toad-eradication-app.html`. To re-validate the forms:
```
pip install pyxform   # throwaway venv, not the system Python
xls2xform --odk_validate --pretty_print toad_eradication_site.xlsx toad_eradication_site.xml
xls2xform --odk_validate --pretty_print toad_eradication_session.xlsx toad_eradication_session.xml
```
Commit the regenerated `.xml` alongside the `.xlsx`.

## Two forms

- **Sites are submitted on their own, before any session can use them.** On the first night at
  a site, one person creates it and the others need it before they can start. A site therefore
  can't be created as a side effect of a session, as the toad app does.
- **The session form has no entity block.** A session only carries the site's entity id
  (`site_id`, a `select_one_from_file toad_eradication_sites.csv`, which exists only so
  Central attaches the CSV to the manifest). Central accepts a session whether or not the site's
  own submission has reached it yet.
- Sessions also carry a snapshot of `site_name`/`site_lat`/`site_lon`. If the creator's phone
  never syncs the site, the warehouse can still recover it from teammates' sessions.
- **The site form is create-only** (entities sheet: `dataset` + `label`, no `entity_id`/
  `create_if`/`update_if`). pyxform's upsert form (`entity_id` + `update_if`) needs the
  dataset attached to the form itself, and ODK Validate fails without it.
  - The compiled form fills `meta/entity/@id` with `uuid()`. `buildSiteXml()` sends **our own
    UUID** there instead (`rec.site_id`), because teammates may already have that id from the
    QR code.
  - **Verified against the live Central (2026-11-06):** Central keeps a client-supplied `id`
    on a create-only form's `<entity>`. A site registered from the app (desktop) came out with an
    entity UUID equal to the submission's `site_id`.
- Both forms submit to the same project `/submission` URL; the `<data id>` root picks the form.
  `trySyncAll()` sends site records before session records.

## Getting a new site onto teammates' phones

Two paths, both always available:
1. **QR code (no signal needed).**
   - After creating a site, the creator's phone shows a QR code (`openShareSheet()`). It can
     also be shown from a running session, or from idle via "Show a site's QR".
   - The payload is `{"t":"tcz-erad-site","v":1,"id","name","lat","lon"}`, generated by the
     vendored `qrcode-generator` (an encoder; jsQR only decodes).
   - Teammates scan it from the site picker (`startScan('site')` → `acceptScannedSite()`), which
     stores it in `sharedSites` (`tcz_erad_shared_sites_v1`). `allKnownSites()` merges that list
     in.
   - The scanner rejects any payload without `t: "tcz-erad-site"`.
2. **Central polling.**
   - While the site picker is open and online, `refreshSiteList()` refetches the manifest CSV on
     opening and every 20 s (`SITE_POLL_MS`).
   - The fetches use `cache: 'no-store'`. `sw.js` only caches same-origin requests and Esri
     tiles. (The toad app's `sw.js` caches every GET, Central's CSV included, so its first
     refresh can return a stale copy. Don't copy that here.)
   - How fast a new entity appears in the manifest CSV after its submission hasn't been measured
     against a live Central yet.

Site precedence in `allKnownSites()`: Central's CSV, then this phone's own site records, then
teammate-shared sites.

## Session specifics

- `sessionState` is `idle → running → stopped → idle`, as in the track app's walk.
  - The site picker (`openSiteSheet('start')`) sits in front of `running`, and Start requires a
    collector name in Settings.
  - End needs the `#endConfirmOverlay` sheet. The end sheet has no backdrop dismiss, and 🗑 →
    Resume/Discard.
- **Captures** are rows of the `capture` repeat:
  - `capture_type` is `caught`|`escaped`. `capture_count` is 1, or N via "Caught several",
    whose time is taken at the first tap (`pendingMultiMs`). `capture_seconds` is elapsed
    seconds.
  - `toads_caught`/`toads_escaped` are the totals, as a cross-check.
  - A session with no captures emits no `<capture>`. That's valid: a real zero.
- No per-toad GPS: the ETL interpolates position from `session_track` + `session_track_seconds`
  using `capture_seconds`.
- **Time fields.**
  - `startTs` is the clock origin and is shifted on Resume, so paused time isn't effort and isn't
    counted in `duration_seconds` / `capture_seconds` / track seconds.
  - `startedAt`/`endedAt` are the real wall-clock times, used for `start_date`, `start_time` and
    `end_time`.
  - `night_date` is the local date of `start − 12 h`, so a 00:30 start belongs to the previous
    evening.
  - `registered_at` (site form) is an ODK `dateTime` with the device's UTC offset
    (`localIsoDateTime()`).
- `device_id` is a random UUID per install (`settings.deviceId`), so two phones with the same
  collector name stay distinguishable.
- The wake lock is held for the whole session (a locked phone stops a web app's geolocation).
  The night theme keeps the always-on screen dim. Every capture vibrates where supported.
- The clock shows `H:MM:SS` once a session passes an hour.

## Styling

A dark night palette (`--night`, `--panel`, `--amber`, `--toad`) so the app is easy to tell
apart from the light-themed sibling apps and is gentle on night vision. The header logo and jsQR
block were copied verbatim from the sibling apps. The Leaflet CSS/JS blocks are the toad app's
vendored 1.9.4. The app icon (an amber tally mark on near-black, as a data URI in
`manifest.json` and the `apple-touch-icon` link) was generated with Pillow. Regenerate it rather
than hand-editing the base64.

## Notes for editing

- Keep the application in the single HTML file. `manifest.json`/`sw.js` are the only sanctioned
  exception, as in the sibling apps.
- Vendored blocks (jsQR, qrcode-generator 1.4.4 (MIT), Leaflet 1.9.4, logo) are pasted
  unmodified. Re-vendor rather than patch them.
- Record field names match the XLSForm `survey` sheet names (no `FIELD_MAP`). If you add a
  field, place its element in `buildSiteXml()`/`buildSessionXml()` at its `survey` sheet
  position and re-validate.
- `crypto.randomUUID()` generates the OpenRosa `instanceID`s and the site entity id
  (`site_id`). Never reuse one for the other.
- Warehouse ETL for these forms isn't built yet (`../data-warehousing`).
